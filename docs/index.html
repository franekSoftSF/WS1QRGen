2 Enrollment token

Use this when enrollment runs through the Android Management API rather than a custom DPC — including Workspace ONE UEM tenants configured for AMAPI enrollment. The token comes from whichever console issues it: your UEM console, or the Android Management API directly.

Sent as com.google.android.apps.work.clouddpc.EXTRA_ENROLLMENT_TOKEN, together with the component com.google.android.apps.work.clouddpc/.receivers.CloudDeviceAdminReceiver and the Android Device Policy download location documented by Google.

Both a UEM console and enrollmentTokens.create can hand you a complete payload (the qrCode field of the enrollment token). Paste it here — the WiFi, locale, time zone and provisioning options below are merged in, and everything else is left exactly as it came.

What else can be automated through the token?

These are set when the token is created in the console or through the API — they are not part of the QR code, so they cannot be added here:

  • additionalData — up to 1024 characters of your own metadata (site code, cost centre, inventory number). After enrollment it comes back on the device as enrollmentTokenData, which makes it the practical hook for automating what happens next.
  • policyName — the policy applied the moment the device enrolls.
  • oneTimeOnly — the token stops working after one device uses it.
  • duration — how long the token stays valid (default one hour).
  • allowPersonalUsage — whether a company-owned device may also have a work profile.

3 Network

The QR code carries no network settings at all, so the device shows its own WiFi picker during setup: the person enrolling selects the network and types the password there. The WiFi password never ends up inside the code.

Anyone who scans or photographs this code can read the WiFi password out of it.

4 Region and options

Both optional — leave them empty and the device asks during setup. Start typing to filter; the lists hold every locale and time zone Android 9+ accepts.

Turn the first one on if devices should keep the manufacturer's factory apps; with it off, provisioning disables system apps that are not part of the managed set.

About this tool and what it can generate

A device-owner QR code is a small JSON document. Android reads it on a freshly reset device, downloads the management app named in it, and hands over the rest of the setup — which is why the details have to be exactly right, and why a wrong character means a device that has already been wiped and now will not enrol.

  • Workspace ONE UEM, credentials — server, Group ID and an optional staging account.
  • Workspace ONE UEM, token — the token travels in the Group ID field, with no credentials.
  • Enrollment URL — paste a serverurl/gid link from the console and the fields fill themselves.
  • Android Management API — from an enrollment token, or from a ready-made payload the console or API gave you.
  • WiFi — either left to the device, or embedded in the code.
  • Region — locale and time zone from the full Android lists.

Save your settings to a file and load them back on another machine, print an instruction sheet for whoever does the enrolling, and download the code as PNG. Nothing is transmitted: the page has no analytics, no external requests and no server side. Reading the source is enough to confirm that.

It comes from WSO QR, a self-hosted companion for Workspace ONE UEM: bulk enrollment from CSV, day-2 device actions, migration between UEM consoles with a self-service portal, and automatic email notifications.
